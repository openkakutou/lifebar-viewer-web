# Module: i18n
**Role:** This app's own localization setup (backlog item 008): wires the shared `web-ui-kit` i18next integration layer under this app's own namespace (`en.json`/`fr.json` catalogs), and exposes a thin `t(key, defaultValue, vars?)` wrapper that falls back to the interpolated `defaultValue` whenever `initAppI18n` hasn't resolved yet in the page — so most existing tests assert plain English text with no i18n bootstrap of their own. `initAppI18n` is only ever called once, from `main.ts`'s real bootstrap, awaited before the first render so the app never flashes English before a persisted locale resolves. See `.vibe/decisions/007-i18n-integration-approach.md`.
**Files:** `src/i18n/i18n.ts`, `src/i18n/en.json`, `src/i18n/fr.json`, `src/types/web-ui-kit.d.ts`
**Exports:** `NAMESPACE`, `initAppI18n()`, `t(key, defaultValue, vars?)`, `getI18n()`, `onLocaleChange(callback)`
**Depends on:** `@openkakutou/web-ui-kit` (external, `initI18n`/`getI18n`/`onLocaleChange`/`<wuik-locale-switcher>` — roadmap decision `023-localization-approach-for-web-ui.md`; its installed build ships no `.d.ts` of its own, worked around by `src/types/web-ui-kit.d.ts`, the same approach the sibling `lifebar-editor` repo already uses for the same gap)
